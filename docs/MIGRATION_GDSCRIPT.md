# C# → GDScript 전환 기록

2026-08-13에 완료했다. 현재 실행 방법은 [README](../README.md), 구조는 [CODE_GUIDE](CODE_GUIDE.md)를 따른다. 아래는 전환 당시의 판단과 보존한 계약이다.

## 목적과 결과

기존 동작과 사용자 데이터를 유지하면서 C#/.NET 의존성을 제거하고 Godot의 씬·signal·입력 구조를 익혔다. 앱과 테스트는 일반 Godot에서 GDScript로 실행한다. .NET SDK와 C# 빌드 단계는 더 이상 필요하지 않다.

## 유효했던 진행 방식

1. 시작 시점의 코드와 테스트를 기준선으로 삼았다. 오래된 기획서의 기능 목록만으로 호환성을 판단하지 않았다.
2. core → storage → 작은 UI → 복합 화면 → 학습 → 앱 조립 순서로 옮겼다.
3. 기능별 실행 구현은 하나만 사용하고, 매 단계에서 테스트와 씬 로드를 확인했다.
4. 씬 구조와 데이터 형식 변경을 언어 전환과 분리했다. 카드 영구 ID나 새로운 학습 규칙을 함께 도입하지 않았다.
5. 전환된 진입점과 참조를 확인한 뒤 C# 파일·프로젝트 파일·dotnet 설정을 제거했다.

## 보존한 데이터 계약

- Markdown의 `# 질문` 구분, 여러 줄·빈 답, 중복 질문을 유지한다.
- 진행도 키는 질문 문자열이다. 중복 질문은 기록을 공유하며, 앱 밖의 질문 변경은 자동 추적하지 않는다.
- 예전 숫자형 오답 기록과 객체형 기록을 모두 읽는다.

```json
{"Apple": 3}
```

```json
{"Apple": {"wrong": 3, "status": "LEARNING"}}
```

현재 형식에는 이후 추가된 필드가 있을 수 있다. 정확한 직렬화는 `src/core/progress.gd`가 기준이다.

## 남은 검증 자산

- [고정 입력](../tests/fixtures/README.md): 파서 경계값, 중복 질문, 예전 진행도, 잘못된 JSON.
- `tests/phase*_smoke.gd`: 계층별 이전 과정에서 만든 회귀 검증. 파일명의 phase는 당시 구분이다.
- `tests/main_smoke.gd`: 앱 조립과 사용자 흐름 검증.
